DETAILS
-------

1. Upgrade Node to 24 LTS
   Node 20 reached end-of-life in April 2026, and the local install
   (20.18, from the nodejs.org installer, owned by root) is too old for
   Vite 8. melonJS 20 also declares "node": ">=24.0.0".
   - Install Node 24 LTS on this machine.
   - Add .nvmrc containing "24" so version managers and CI pick it up.
   - Add "engines": { "node": ">=24" } to package.json.
   - Upgrade vite ^6 -> ^8, then re-run the dev server and build.

2. Dependabot
   Add .github/dependabot.yml with monthly checks for npm and
   github-actions. Small, regular update PRs instead of another
   five-year jump.

3. "private": true
   Prevents an accidental `npm publish` of the game.

4. Ignore .idea/
   JetBrains project files are per-developer; add .idea/ to .gitignore.

5. Manifest fixes (public/manifest.json)
   - Three icon "src" values are missing ".png" (lines 45, 49, 53).
   - Icon paths are absolute ("/icons/..."), which break when served
     from a sub-directory such as /chess-js/ on GitHub Pages; make them
     relative ("icons/...").
   - "developer" is not a standard manifest field; drop it.

6. GitHub Pages deployment
   - Add a workflow (.github/workflows/deploy.yml) that runs
     `npm ci && npm run build` on pushes to main and publishes build/
     with actions/deploy-pages.
   - Switch the repo's Pages source to "GitHub Actions".
   - `git rm -r --cached build`, add build/ to .gitignore.
   - Retire the gh-pages branch once the new deploy is confirmed.

7. Branches
   Open a PR from sandbox to main and merge it. Delete origin/clean if
   it is no longer needed.

8. Biome + CI
   Planned as ESLint + Prettier; Biome was chosen instead, since one
   tool lints and formats with a single config.
   - biome.json with the recommended rules and the existing style
     (2 spaces, double quotes); `npm run lint` checks, `npm run fix`
     applies fixes.
   - .github/workflows/ci.yml: npm ci, biome ci, npm test and the build
     on pull requests and pushes to main.

9. Dead code
   - Unused key bindings (LEFT/RIGHT/A/D) in js/screens/play.js.
   - audio.init() in js/game.js (the game has no sounds).
   - Empty public/data/bgm, map, sfx placeholder folders.
   - Unused methods such as Square/Grave isLocatedAt.

10. Separate rules from rendering + tests
    Board state and move generation currently live in melonJS
    Renderables, and behaviors call app.world directly. Move the
    rules into plain modules with no melonJS imports, keep the
    Renderables as a view layer, then cover moves, captures, castling,
    en passant and promotion with Vitest.

11. Check / checkmate / stalemate
    Done: the king's square turns red in check, and the status line
    above the board shows whose move it is. Checkmate or stalemate shows
    in the status line with "click to continue" below the board, then a
    summary screen (play again / main menu). The game starts at a main
    menu. All text is lowercase, 12pt (title 20pt), and left-aligned
    with the board.

12. Pawn promotion prompt
    Done: when a pawn reaches the last rank, "promote" and the queen,
    rook, bishop and knight in the player's color appear below the
    board, where "click to continue" shows at the end of a game. A
    choice lights up on hover; clicking it promotes the pawn. Pieces on
    the board can't be picked up until then.

13a. Insufficient material
    Done: the game ends as a draw when neither side can checkmate: king
    vs king, king and bishop vs king, king and knight vs king, and kings
    with bishops all on squares of the same color. The status line and
    summary screen name the reason ("stalemate", "insufficient
    material"); 13b's draws can add theirs to drawReason().

13b. Repetition and the 50-move rule
     Done: the rules keep a key for every position reached (pieces, side
     to move, castling rights, and any legal en passant capture) and a
     count of plies since the last capture or pawn move. The game ends as
     a draw automatically at threefold repetition and at 50 moves by each
     side, unless the last move mates. The board also keeps a list of
     the moves played (history), which en passant reads to see whether
     the target pawn's double step was the last move; it could later
     drive a move list on screen, undo, or the summary's move count.

14. Pixel font
    Load a pixel font as a "fontface" resource and set FONT in
    js/ui/text.js to its name. Check SIZE and TITLE_SIZE there too,
    since pixel fonts look sharpest at multiples of their native size.

15. View tests
    The rules have Vitest tests; the menu, board and screens are only
    play-tested. Either save the headless-Chrome driver used so far as
    a project skill (/run-skill-generator), or add a small end-to-end
    test to CI.

16. Touch and phones
    The game scales to the window, but dragging pieces on a phone or
    tablet hasn't been tried. Test it, then fix what doesn't work.

17. Keyboard controls
    For accessibility: move a cursor over the board, pick up and drop
    pieces, and use the menu and summary buttons from the keyboard.
    Input should go through the rules module like mouse moves do.

18. Sound effects
    Moves, captures, check and game end. Needs sound files and
    audio.init() back in js/game.js (removed in item 9).
